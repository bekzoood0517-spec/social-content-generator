# PRD — Social Content Generator

## 1. Summary
A web app where a user describes a topic, business, or idea, picks a social network (Telegram, YouTube, Instagram), and receives ready-to-publish posts generated by the Gemini API. Each post has a title, body text, call to action (CTA), and hashtags. The app offers several variants, streams text as it is written, and keeps a history with one-click copy.

## 2. Problem
Small business owners, freelancers, and creators lose time writing posts that fit each platform's style. Generic chat tools give one long answer with no structure, no platform tuning, and no place to keep results.

## 3. Target users
- Solo entrepreneurs and small shops running their own social accounts
- SMM freelancers who produce content for several clients
- Creators/bloggers who need fast drafts and ideas

## 4. Goals
1. From input to a copy-ready post in under 15 seconds (first text visible in under 2 seconds).
2. Output that fits platform conventions (length, tone, structure).
3. Zero-friction reuse: history and one-click copy.
4. A distinctive, hand-crafted interface (not a typical "AI tool" look).
5. English-first quality: the interface and the default output language are English; other languages are supported as an override.

## 5. Non-goals (v1)
- Direct publishing to social networks
- User accounts, payments, teams in v1 (accounts arrive with history sync in v2)
- Daily or monthly usage limits (none by design; only a short-window anti-abuse limiter exists)
- Image/video generation
- Scheduling or analytics

## 6. Core user flow
1. Enter a topic/description (free text).
2. Choose a network: Telegram, YouTube, or Instagram.
3. (Optional) tune tone, language, and number of variants.
4. Press Generate.
5. Variants appear and stream in gradually.
6. Pick one, copy the whole post or any single part (title / text / CTA / hashtags).
7. Result is saved automatically to history.
8. Later: open history, re-copy, delete, or regenerate from the same input.

## 7. Features

### 7.1 Input
- Text area for topic/business/idea description (max 1,000 characters, with counter)
- Network selector (3 options)
- Options: tone (neutral, friendly, expert, bold), language (English by default, manual override to any other language), variants count (1–4, default 3)

### 7.2 Generation
- Per-network output structure:
  - **Telegram:** headline, body with short paragraphs, CTA, 3–5 hashtags
  - **Instagram:** hook title, caption with line breaks, CTA, 8–15 hashtags
  - **YouTube:** video title (≤70 chars), description with CTA, 5–10 tags/hashtags
- Multiple variants generated in parallel, each with a distinct angle
- Gradual (streaming) text display per variant
- "Pre-generation": see 7.3

### 7.3 Pre-generation
Interpreted as: the app prepares work before the user asks.
- On network/topic change (debounced, after the user pauses typing), a lightweight call prefetches a short "angle suggestions" list (3 angles) so full generation starts with a better brief.
- Optional: warm the generation by starting variant 1 once the user has filled the input and picked a network and stays idle for 2s (cancelable). Behind a setting, off by default, to control API cost.

### 7.4 Results
- Variant cards or tabs, each showing title, text, CTA, hashtags as separate blocks
- Copy buttons: whole post and each block
- Regenerate single variant; regenerate all
- Basic inline editing before copying

### 7.5 History
- Stored locally in the browser (v1)
- List with date, network, input snippet, selected variant preview
- One-click copy of the post directly from the list
- Open, delete, clear all, search by text
- Limit: last 200 entries
- Built to be sync-ready: every entry has an id, timestamps, and a schema version so cross-device sync (v2) can be added without a data migration

## 8. Functional requirements (summary)
| ID | Requirement | Priority |
|----|-------------|----------|
| F1 | Generate posts for 3 networks with defined structure | Must |
| F2 | 1–4 variants per request | Must |
| F3 | Streaming display | Must |
| F4 | One-click copy (whole and per block) | Must |
| F5 | History with persistence | Must |
| F6 | Pre-generation (angle suggestions) | Should |
| F7 | Tone and language controls | Should |
| F8 | Inline editing | Should |
| F9 | Regenerate single variant | Should |
| F10 | Export history (JSON/CSV) | Could |
| F11 | Cross-device history sync with sign-in | v2 |
| F12 | English-first UI and default output language | Must |

## 9. Non-functional requirements
- **Security:** Gemini API key never exposed in the browser; all calls go through a backend proxy.
- **Performance:** first token under 2s on typical connection; UI stays responsive during streaming.
- **Reliability:** graceful handling of rate limits, timeouts, and safety-blocked responses, with retry.
- **Responsive:** works on mobile and desktop.
- **Accessibility:** keyboard operable, visible focus, sufficient contrast, reduced-motion support.
- **Privacy:** in v1 history stays on the user's device and no input is stored on the server. In v2, sync is opt-in and requires sign-in.

## 10. Success metrics
- Time to first visible text (median) < 2s
- Share of sessions with at least one copy action > 70%
- Average variants viewed per session
- Regeneration rate (lower = better first-try quality)
- Error rate of generation < 2%

## 11. Risks and mitigations
| Risk | Mitigation |
|------|------------|
| API cost growth | No daily limit, so control cost with a 4-variant cap, a short-window burst limiter per IP, pre-generation off by default, and spend alerts on the API key |
| Inconsistent output format | Structured JSON output schema, validation, auto-retry |
| Key leakage | Backend proxy, env variables, no client-side key |
| Generic "AI-sounding" text | Prompt tuning per network, tone presets, banned-phrase list |
| Safety blocks on legitimate input | Clear error message, suggest rephrasing |

## 12. Milestones
1. **M1:** Backend proxy + single-variant generation for one network
2. **M2:** All 3 networks, structured output, multiple variants
3. **M3:** Streaming UI, copy actions
4. **M4:** History, editing, regeneration
5. **M5:** Pre-generation, polish, accessibility pass
6. **M6:** Deploy and monitor
7. **v2 (next):** Sign-in, cloud history, and cross-device sync (local-first, merge by timestamp)

## 13. Decisions
- **Language priority:** English. UI copy, default generation language, and prompt tuning target English first. Other languages stay available through the language selector.
- **Usage limits:** no daily limit. Only a short-window burst limiter protects against abuse.
- **History sync:** yes, planned for v2. v1 stays local-only but is designed so sync can be added later.
